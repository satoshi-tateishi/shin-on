# Phase 6: 在庫管理システム 詳細仕様書

## 📋 システム概要

### プロジェクト名
**shin-on 機材管理システム Phase 6: 在庫管理**

### 目的
演劇・ミュージカル公演における機材の在庫状況を正確に把握し、効率的な在庫管理を実現するシステム。基準日指定での在庫照会、倉庫別在庫管理、機材移動履歴の可視化を通じて、機材運用の最適化を図る。

### システム位置づけ
- **Phase 1-5**: 基盤・公演管理・機材使用・修理管理・スケジュール表（完了済み）
- **Phase 6**: 在庫管理システム（本仕様書対象）
- **Phase 7**: 統合・最適化（予定）

---

## 🎯 機能要件

### 1. 基準日指定在庫表示機能

#### 1.1 概要
任意の基準日時点での全機材の在庫状況を表示する機能。過去・現在・未来の在庫状況を正確に算出し、業務計画の支援を行う。

#### 1.2 詳細機能
- **基準日選択インターフェース**
  - カレンダーピッカーによる日付選択
  - 過去1年〜未来6ヶ月の範囲で選択可能
  - デフォルト：現在日付

- **在庫一覧表示**
  - 機材名・カテゴリ・現在庫数・総数・使用中数の表示
  - カテゴリ別・サブカテゴリ別の階層表示
  - 在庫状況による色分け表示（十分・注意・不足）

- **フィルタリング機能**
  - カテゴリ・サブカテゴリによる絞り込み
  - 在庫状況による絞り込み（在庫あり・在庫なし・要注意）
  - 機材名による検索

- **ソート機能**
  - 機材名（昇順・降順）
  - 在庫数（昇順・降順）
  - 最終移動日（昇順・降順）

#### 1.3 出力機能
- **CSV出力**: 一覧データのCSV形式出力
- **Excel出力**: 見やすい形式でのExcel出力
- **印刷機能**: ブラウザ印刷に最適化された表示

### 2. 倉庫別在庫管理機能

#### 2.1 概要
各倉庫・保管場所毎の在庫状況を管理し、機材の物理的な所在を明確にする機能。

#### 2.2 詳細機能
- **倉庫別在庫一覧**
  - 倉庫毎の在庫数表示
  - 倉庫の収容率・使用率表示
  - 倉庫毎の機材カテゴリ分布

- **倉庫間移動管理**
  - 倉庫間移動登録フォーム
  - 移動理由・実行者・日時の記録
  - 移動承認ワークフロー（必要に応じて）

- **倉庫容量管理**
  - 倉庫毎の収容可能数設定
  - 収容率アラート機能
  - 最適配置提案機能

#### 2.3 在庫移動機能
- **個別移動**: 単一機材の倉庫間移動
- **一括移動**: 複数機材の同時移動
- **セット移動**: 機材セット単位での移動

### 3. 機材移動履歴機能

#### 3.1 概要
全機材の移動履歴を時系列で表示し、機材の使用パターンや問題の分析を支援する機能。

#### 3.2 詳細機能
- **移動履歴タイムライン**
  - 機材毎の移動履歴を時系列表示
  - 移動タイプ別の色分け表示
  - 移動理由・実行者・備考の表示

- **移動履歴検索**
  - 期間指定による履歴検索
  - 移動タイプによる絞り込み
  - 実行者による絞り込み

- **移動統計**
  - 機材別移動頻度統計
  - 倉庫間移動パターン分析
  - 移動理由別統計

#### 3.3 分析機能
- **使用パターン分析**: 機材の使用頻度・パターンの可視化
- **問題箇所特定**: 移動の多い機材・問題のある倉庫の特定
- **効率化提案**: 移動データに基づく配置最適化提案

### 4. 在庫アラート機能

#### 4.1 概要
在庫状況に基づくアラート・通知機能。在庫不足や過剰在庫の早期発見と対応を支援。

#### 4.2 詳細機能
- **在庫不足アラート**
  - 機材別最小在庫数設定
  - 在庫不足時の自動アラート
  - アラート対象者への通知

- **過剰在庫アラート**
  - 長期間未使用機材の検出
  - 倉庫容量超過アラート
  - 廃棄・処分提案

- **メンテナンスアラート**
  - 定期メンテナンス時期の通知
  - 故障率の高い機材の特定
  - 予防保全提案

### 1. データベース設計

#### 1.1 新規テーブル

##### inventory_snapshots テーブル
```sql
CREATE TABLE inventory_snapshots (
    id BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
    snapshot_date DATE NOT NULL COMMENT 'スナップショット日付',
    equipment_id BIGINT UNSIGNED NOT NULL COMMENT '機材ID',
    location_id BIGINT UNSIGNED NULL COMMENT '場所ID',
    quantity INT NOT NULL COMMENT '在庫数量',
    total_quantity INT NOT NULL COMMENT '総数量',
    created_at TIMESTAMP NULL,
    updated_at TIMESTAMP NULL,

    FOREIGN KEY (equipment_id) REFERENCES equipments(id) ON DELETE CASCADE,
    FOREIGN KEY (location_id) REFERENCES locations(id) ON DELETE SET NULL,

    INDEX idx_snapshot_date (snapshot_date),
    INDEX idx_equipment_snapshot (equipment_id, snapshot_date),
    INDEX idx_location_snapshot (location_id, snapshot_date),

    UNIQUE KEY uk_snapshot_equipment_location (snapshot_date, equipment_id, location_id)
);
```

#### 1.2 既存テーブル活用
- **equipment_movements**: 移動履歴（既存・活用）
- **equipments**: 機材マスタ（既存・一部拡張）
- **locations**: 場所マスタ（既存・一部拡張）

##### InventorySnapshot モデル
```php
class InventorySnapshot extends Model
{
    protected $fillable = [
        'snapshot_date',
        'equipment_id',
        'location_id',
        'quantity',
        'total_quantity'
    ];

    protected $casts = [
        'snapshot_date' => 'date',
        'quantity' => 'integer',
        'total_quantity' => 'integer'
    ];

    // リレーション
    public function equipment(): BelongsTo
    public function location(): BelongsTo

    // スコープ
    public function scopeAsOfDate($query, $date)
    public function scopeForLocation($query, $locationId)

    // 静的メソッド
    public static function createSnapshot($date): void
    public static function getInventoryAsOf($date, $filters = []): Collection
}
```
